🔐 ADVANCED • API keys and access tokens

Optional extension • 10–15 minutes • Safe classroom simulation • No real credentials needed

What are they?

API: an application programming interface lets software request information or actions from another service.

API key: an identifier a service may use to recognise an application or project, apply quotas, or authorise particular requests. Some keys are deliberately public (such as certain browser Firebase configuration keys); others are secret.

Access token: a credential often issued after authentication, which may represent a user or application's permissions for a limited period. A bearer token must be protected: whoever possesses it may be able to use it until it expires or is revoked.

Important: A key or token is not automatically encrypted, and not every API key is a secret. Real protection depends on authentication, permissions, server-side checks and security rules.

🕵️ Operation Ghost Protocol • incident investigation

Extension tasks D–J • approximately 15–20 additional minutes • fictional evidence only. Work in pairs and justify every conclusion.

New evidence: A security analyst has recovered a short extract from Northstar Robotics' equipment API logs. All details below are fictional.

18:39:12 | 192.0.2.24 | GET /api/assets/NR-042 | 200 OK
18:40:03 | 192.0.2.24 | GET /api/assets/NR-042 | 403 Forbidden
18:40:55 | 198.51.100.18 | GET /api/assets/NR-042 | 401 Unauthorized
18:41:10 | 192.0.2.24 | GET /api/assets/NR-042 | 403 Forbidden
18:43:06 | 203.0.113.7 | GET /api/assets/NR-042 | 200 OK

The addresses belong to documentation-only IP ranges; they do not identify real users. A successful API request is not proof that a person physically moved the laptop.

Task D — Reconstruct the timeline: Which request happened first, which happened last, and how much time elapsed between them?

Task E — Interpret the responses: Explain the difference between 200 OK, 401 Unauthorized and 403 Forbidden. Why might the same IP address receive different results?

Task F — Challenge the evidence: Does the 18:43 successful request prove who stole the laptop? Give two reasons why the log alone is insufficient.

Task G — What would you investigate next? Choose the most useful next source of evidence.

Task H — Assess the exposed token: If a bearer token appears in a public screenshot, what immediate actions should the security team take? What would they check before concluding whether it was misused?

Task I — Investigate the unusual sequence: Write two plausible explanations for the 200 → 403 pattern at 192.0.2.24. What additional evidence would distinguish between them?

Task J — Present your findings: Write a short incident report using the headings What we know, What we suspect, What we still need, and Recommended next action. Avoid claiming certainty where evidence is missing.

Detective reminder: An IP address is not a person; a timestamp is not an eyewitness; an HTTP success code is not proof of theft. Good investigators distinguish observations from interpretations.
